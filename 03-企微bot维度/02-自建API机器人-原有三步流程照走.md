# 2 自建 API 机器人：原有三步流程照走

**结论**：要搭**专用自动化 bot**（补料机器人、定时汇总、群内问答库等），走的还是前库 [bot-OA-SOP](https://github.com/ddd-agent-assets/bot-OA-SOP) 的老流程——**管理员建号（API 模式 + 长连接）→ 发布两轮审批 → 授权三步**。WorkBuddy 官方融合形态（通讯录机器人/大圆/客户端）**不能替代**这种自建通道：自建 bot 是"自己养的工具"，自由度最高、流程也最重。两者不冲突、可并存。

## 一、什么时候自建，什么时候用官方形态

| 场景 | 选择 |
| :--- | :--- |
| 个人/团队的通用 AI 办公（整理、写、查、改文档） | 官方形态（WorkBuddy 六形态，见[[00-总览/01-三个角色-WorkBuddy大圆企微bot是什么关系|总览：三个角色]]） |
| 长期专用自动化（每晚拉 ETA 写表、异常告警推送） | **自建 API 机器人**（本篇） |
| WorkBuddy 定时任务能覆盖的轻量自动化 | 先试 WorkBuddy 自动化，不够再自建 |

> 提示：WorkBuddy 的"助理"功能（5.5.6 起）也要**绑定一个企微机器人**才能远程触发桌面任务——绑定的机器人同样按本篇流程创建。

## 二、三步流程浓缩版（全量细节看前库）

| 步骤 | 谁做 | 在哪做 | 要点 |
| :--- | :--- | :--- | :--- |
| **1. 建号开权限** | 管理员（企微超级管理员） | 企微管理后台：安全与管理 → 管理工具 → 智能机器人 → 创建机器人（有权限的成员可从客户端"工作台"进）→ **手动创建 → API 模式 → 长连接** | 拿到 **Bot ID + Secret** 妥善保存（泄露=任何人可冒用机器人）；配**可用范围**（只开给实际使用者）；权限默认全关，**12 类逐项开** |
| **2. 发布两轮审批** | 提交者 → 上级 → 管理员 | 机器人发布动作 | 上级审批人**自己选、系统不带出直属上级**，自觉选对人；申请原因**一句话三带**：干什么、哪张表（新/旧）、读还是写 |
| **3. 授权三步** | 管理员 → 搭建者本人 → 数据负责人 | 建号开权限（每机器人一次）→ **本人扫码**授权（每人一次，不能代办）→ **发文档链接**给机器人（每文档一次，大企业必做） | 授权只给"读"；官方写明授权有效期 **7 天**（与实测长期有效存在矛盾，报无权限先重新扫码） |

## 三、不变的硬边界（与 WorkBuddy 官方形态完全一致）

- **写只写自建**：机器人永远写不了员工建的旧表，解法是"机器人建新表记新数据，旧表挂索引"；
- **读要授权 + 发链接**；
- **不冒充员工**：不能以员工名义发消息；机器人只有创建者本人能对话，**一人一个机器人**；
- 智能表格 20 人授权上限、权限三档、"下载-上传"覆盖他人修改等全部红线见[[04-通用规则/02-红线速查-批了也没用别硬闯|通用规则：红线速查]]。

## 四、接入工具

- 官方 CLI：`npm install -g @wecom/cli`（Node.js ≥ 18）+ `npx skills add WeComTeam/wecom-cli -y -g` + `wecom-cli auth init` 扫码配置；
- MCP 通道：API 模式机器人支持 MCP 调用（streamableHTTP URL / JSON Config）；
- **不需要公网服务器**，公司内网也能跑（长连接）。
