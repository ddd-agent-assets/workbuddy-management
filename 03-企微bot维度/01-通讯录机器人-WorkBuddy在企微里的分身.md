# 1 通讯录机器人：WorkBuddy 在企微里的分身，私聊、拉群、进频道

**结论**：企业授权后，WorkBuddy **以可对话机器人的身份进入企业通讯录**——它是 WorkBuddy 在企微里的"分身"，与 WorkBuddy 客户端**上下文双端同步**（企微里聊一半，客户端接着说）。三种用法：**私聊**派活、**拉群 @** 协作、进**频道**（灰度）。

## 一、三种用法

| 用法 | 怎么做 | 适合 |
| :--- | :--- | :--- |
| **私聊** | 通讯录找到 WorkBuddy 机器人，直接对话派活 | 个人任务：整理资料、写草稿、查日程 |
| **拉群 @** | 把机器人拉进项目群，@ 它处理任务 | 团队协作：群内问答、汇总讨论 |
| **频道** | 企微灰度内测的「频道」功能（项目协作、收集意见、分享知识），可添加机器人进频道协作 | 项目制协作；**没看到入口是灰度常态，不是故障** |

## 二、群内 @ 的三条注意

1. **材料随消息发**：需要 AI 处理的方案正文或有权限的附件，**随本次 @ 消息一起发**——机器人不默认读取 @ 之前的全部群聊；
2. **回复当草稿用**：机器人回复是辅助产出，不当正式结论（法律、财务意见必须走人工复核）；
3. **核对实际收到什么**：让机器人复述一遍收到的材料范围再开工，避免"以为它读了其实没读"。

**群内 @ 范本**：

> @WorkBuddy 请只根据本次消息附带的《项目方案》，列出 3 个需要继续确认的风险点，每项指出对应原文；资料没提到的写"待确认"。

## 三、双端同步是怎么回事

企微端内机器人与 WorkBuddy 客户端（同企微账号登录）**上下文双端同步**（智东西 2026-10-14 实测）。典型用法：

- 早上在企微私聊里让 AI 起草周报 → 中午回客户端，同一个任务里让它继续排版、生成文档；
- 客户端开了长任务 → 人在外面，企微里问进度、补充要求。

## 四、前提条件

- 企业已授权开通、你的席位已领取（[[01-WorkBuddy维度/02-开通条件与领取席位|WorkBuddy篇：开通与领席位]]）；
- 双端版本达标（企微 ≥ 5.0.12、WorkBuddy ≥ 5.0.12 对应的融合版本，见[[01-WorkBuddy维度/02-开通条件与领取席位|WorkBuddy篇：开通与领席位]]）；
- **企微里看不到 WorkBuddy** → 公司没开通（找管理员）或你不在可见范围（让管理员加）。
