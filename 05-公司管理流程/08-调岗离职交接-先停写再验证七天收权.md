# 8 调岗离职交接：先停写、再验证、重新授权、七天后收权

**结论**：用 WorkBuddy 的同事（尤其是搭了场景/机器人/定时任务的人）调岗或离职，按这四步交接。WorkBuddy 时代要交接的资产从"机器人+表+脚本"扩成**七样**：账号、席位、连接器授权、机器人/智能体、定时任务与通知通道、GitHub 仓库、台账。前提仍是[[05-公司管理流程/03-登记台账-在线表格|管理流程：登记台账]]登记完整——没台账就没有交接。

## 交接时间轴

**D0 停写 → D0+ 双人验证 → D1-6 重新授权 → D7 收权**

## 第一步：停写（D0）

台账里该同事名下的资产先**全部停写**（保留查看）：

- 自建机器人停写、定时任务**停用**（不只是断通知——任务本身也要停，防止继续烧积分）；
- 会话内编辑类场景停用；连接器**先不急着解绑**（验证要用），但停止新增授权。

## 第二步：双人验证（交接双方一起）

| 验证项 | 验什么 |
| :--- | :--- |
| 席位 | 管理后台席位归属清楚，新负责人已分到席位 |
| 机器人/智能体 | 能用吗；可见范围对吗 |
| 表/文档权限 | 新旧表关系清楚，权限按[[04-通用规则/01-授权边界-敏感操作本人授权代发要确认|通用规则：授权边界]]重新走 |
| 定时任务 | 任务清单、触发规则、通知通道都在运行记录里可查 |
| 连接器 | 清单核对：哪些保留（新负责人重新授权）、哪些解绑 |
| 积分/加购包 | 剩余额度、加购包到期时间 |
| GitHub 仓库 | 公司仓库在 [ddd-agent-assets](https://github.com/ddd-agent-assets) 能打开，权限找 Rosetta/Yomi 调整 |
| 大圆专项 | **停**（定时任务看板暂停/删除在跑任务）→ **清**（最近任务列表删除，含云端产物）→ **解**（解除与 WorkBuddy 机器人的关联、关"保持电脑唤醒"）；完整四步见 [[02-大圆维度/03-大圆怎么管-范围最小敏感群禁用月审\|大圆篇：怎么管]]第六节 |

## 第三步：重新授权（D1-6）

平台规矩：**权限不跟人走**。新负责人要：

- 重新扫码授权 + 重发文档链接（自建机器人场景）；
- 连接器按清单**本人重新授权**（旧授权随旧账号失效/回收）；
- 企微账号在新设备/新人处重新登录。

## 第四步：收权（D7）

- 管理后台**收回席位**、移出"允许的成员"；
- 解绑该同事全部**连接器授权**与**助理通道绑定**（手机丢失/离职同款处理）；
- 移除其对机器人/智能体/知识库的可见范围；
- 台账更新负责人，交接才算完成。

> 敏感及以上数据场景，收权后按[[04-通用规则/03-数据分级-什么数据可以交给AI|通用规则：数据分级]]做一次数据处理路径复查（日志在 WorkBuddy 管理后台可查）。
