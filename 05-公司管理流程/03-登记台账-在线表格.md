# 3 登记台账：每个场景都要进在线表格，没台账就没有交接

**结论**：每个 WorkBuddy 使用场景（含自建机器人）**上线前必须登记到在线台账**。前库的教训仍然成立：搭东西的人调岗——"她搓的东西怎么交给要使用它的人？"没有台账就没有交接，人一走资产就成孤儿。台账字段在前库七字段基础上**扩了五个 WorkBuddy 字段**。

## 台账在哪

暂行方案：WorkBuddy 场景与机器人的登记与维护记录，统一用**企业微信在线表格**做台账（入口汇总见[[06-提议与附录/02-配套资产-公司GitHub与登记台账|配套资产]]；目前为客服部表，其他部门先按本文字段自建部门表，企业通用版建好后迁移）。

## 登记什么（12 字段）

| 字段 | 说明 | 新旧 |
| :--- | :--- | :--- |
| 负责人 | 谁搭的、谁在用 | 沿用 |
| 机器人/智能体 | 名称 + Bot ID（自建机器人才有 Bot ID） | 沿用 |
| 授权人 | 谁扫码/点击授权的（含连接器授权人） | 沿用 |
| 表清单 | 读写哪些表/文档（含新旧表关系） | 沿用 |
| 额度 | 席位归属、积分/加购包情况 | 扩展 |
| 交接人 | 负责人不在时谁接手 | 沿用 |
| 代码/配置仓库 | 脚本、提示词、mcp.json 存的公司 GitHub 仓库地址 | 扩展 |
| **使用形态** | 六种形态用了哪几种（侧边栏/通讯录机器人/大圆/客户端/session直连/自建API） | **新增** |
| **连接器清单** | 接了哪些连接器、各自授权范围、谁授权的 | **新增** |
| **大圆关联** | 是否关联了大圆、**常用检索范围（哪些群）**、是否涉及敏感群（管理口径见[[02-大圆维度/03-大圆怎么管-范围最小敏感群禁用月审\|大圆篇：怎么管]]） | **新增** |
| **定时任务** | 任务名、触发时间、通知通道 | **新增** |
| **账号类型** | 企微账号 / 其他（工作场景应一律企微账号） | **新增** |

## 什么时候登记、什么时候更新

- **上线前**：[[05-公司管理流程/02-上线检查清单-打勾才可上线|管理流程：上线清单]]全部打勾后登记，不登记不上线；
- **变更时**：换表、扩权限、换负责人、**新增连接器或定时任务**，台账同步改；
- **交接时**：按[[05-公司管理流程/08-调岗离职交接-先停写再验证七天收权|管理流程：交接]]走完，台账更新后才算交接完成。

> 给 IT 的一句话：台账本身可以用"session 直连连接器"让 AI 帮忙维护（读旧表汇总、登记新行写自建表），但**台账登记动作的完整性由负责人签字确认**，不全靠 AI。
