# 4 配置存公司 GitHub：必须公司邮箱注册，仓库必须私有

**结论**：WorkBuddy 场景的配置、提示词、脚本是公司资产，**统一存公司 GitHub 组织 [ddd-agent-assets](https://github.com/ddd-agent-assets)**。两条硬规矩不变：**GitHub 账号必须用公司邮箱注册（禁止个人邮箱）；仓库必须设为 Private（禁止公开）**。WorkBuddy 时代新增一条：**凭证（Bot ID/Secret、连接器 token、mcp.json 里的密钥）一律不入库**。

## 存什么（比以前多了）

| 类型 | 举例 |
| :--- | :--- |
| 自动化脚本 | 自建机器人的脚本、定时任务的外部脚本 |
| 提示词 | 专家/智能体的系统提示词、任务提示词模板 |
| 配置文件 | mcp.json（**脱敏后**）、连接器配置说明、模型选择记录 |
| 使用说明 | README：场景是什么、谁负责、依赖哪些连接器和表 |

## 三条硬规矩

| 事项 | 规矩 |
| :--- | :--- |
| 组织地址 | <https://github.com/ddd-agent-assets>（管理员：AIC Rosetta、客服主管 Yomi） |
| 账号 | 自行注册 GitHub 账号，**必须用公司邮箱** |
| 可见性 | 一律 **Private**；建仓库默认可能是 Public，**建完立刻检查设置** |
| **凭证** | **Bot ID/Secret、连接器 token、API key、mcp.json 密钥——只填在对应配置界面，绝不入库、不贴对话、不发截图** |

> 为什么凭证这条单列：WorkBuddy 时代连接器多了（每个连接器一份授权）、自定义 MCP 的 mcp.json 里可能带密钥——泄露一份等于把对应服务的钥匙交给全网。mcp.json 入库前先删掉密钥字段，配一个"凭证占位符 + 私下传递"的说明。

## 上手三步

1. 用**公司邮箱**注册 GitHub 账号；
2. 把账号名报给 Rosetta 或 Yomi，拉进 ddd-agent-assets 组织；
3. 在组织下建 **Private** 仓库，把配置、提示词、说明传上去，仓库地址登记到[[05-公司管理流程/03-登记台账-在线表格|管理流程：登记台账]]的"代码/配置仓库"列。

## 与 WorkBuddy 的联动

- 客户端会话内可以让 AI 直接从 GitHub 仓库读 README/提示词来复用（通过自定义 MCP 或复制粘贴均可）；
- 仓库地址进台账，交接时新负责人照仓库 + 台账就能接手（见[[05-公司管理流程/08-调岗离职交接-先停写再验证七天收权|管理流程：交接]]）。
